# 진행 현황

## 1. 문서 목적

이 문서는 현재 구현 진행 상태를 기록하는 작업 기준 문서다.  
설계 문서와 달리 아래 내용을 중심으로 계속 갱신한다.

- 실제 구현 완료 범위
- 화면/API 연동 상태
- 최근 수정 사항
- 현재 남은 작업
- 배포/테스트 시 주의 사항

기준 원칙:

- 기능 하나가 끝나면 이 문서를 갱신한다.
- 설계는 `docs`에 남기고, 실제 작업 진척은 `chl`에 남긴다.
- 구현 완료와 “설계만 끝난 상태”를 구분해서 적는다.

## 2. 최신 반영일

- 2026-03-18

## 3. 현재 기준 요약

현재까지는 마이페이지의 핵심 뼈대와 대시보드 요약, 상세 개인정보 화면, 배송지 관리 기능까지 구현이 진행된 상태다.  
주문 목록과 주문 상세는 실제 API 연동이 완료되어 화면에서 확인 가능하고, 대시보드 상단 KPI도 실제 DB 기준 값으로 내려오도록 연결되어 있다.

회원정보는 조회/수정이 실제 반영되는 수준까지 확인했고, 상세 개인정보 페이지와 비밀번호 변경 API도 연결됐다.  
배송지 삭제도 프론트/백엔드 기준으로 연결이 끝났고, 기본 배송지 삭제 제한 정책까지 반영됐다.  
반면 리뷰관리, 찜한상품, 대시보드 차트/패턴 영역, 회원정보 중복 체크, 배송지 수정은 아직 남아 있다.

## 8. 작업 중 확정된 정책

### 주문 / 절약 관련

- 주문 시점 절약률은 `OFT_ORDER_ITEM.SAVING_RATE`에 저장하는 방향으로 확정
- 주문 상세 / 대시보드의 절약률은 주문 시점 기준 값을 사용
- 찜한상품 혜택 문구는 현재 상품 기준 표시용 값으로 분리

### 마이페이지 구조

- 마이페이지와 대시보드는 별도 메뉴로 분리
- 마이페이지는 관리형 화면, 대시보드는 분석형 화면으로 역할 분리
- 주문내역은 목록 + 상세 패널 구조로 진행
- 개인정보는 간략 카드와 상세 페이지로 분리
- 상세 페이지에서는 읽기 전용 정보와 수정 가능한 정보를 분리해서 노출

### 배송지 정책

- 기본 배송지 삭제 전에는 사용자가 다른 주소를 먼저 기본 배송지로 바꾸는 방식 채택
- 배송지 추가 화면은 목록과 분리된 단일 입력 모드 사용
- 배송지 삭제는 가능하지만, 기본 배송지는 다른 주소가 남아 있으면 바로 삭제하지 않음

### 프론트 / 백엔드 연동 기준

- 프론트 API 경로는 `/api/...` 기준으로 통일
- 로그인 미구현 단계에서는 `X-USER-NO` 헤더로 임시 사용자 식별

## 9. 배포 및 테스트 메모

- 현재 개발 환경은 소스와 톰캣 실행본이 자주 어긋나는 문제가 있음
- 특히 아래 경로 기준 확인이 자주 필요함
  - `WEB-INF/classes`
  - `WEB-INF/lib`
  - `WEB-INF/mybatis/mapper`
- 컨트롤러/DTO/서비스 변경 후에는 톰캣 재시작 또는 재배포 확인이 필요함
- 일부 클래스는 IDE가 정상 class가 아닌 stub class를 올리는 경우가 있었음
- Java 버전 불일치 문제로 배포본 class 파일 버전 확인이 필요했던 이력이 있음
