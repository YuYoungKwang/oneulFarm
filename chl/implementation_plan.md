# 구현 계획

## 1. 문서 목적

이 문서는 처음 합의했던 구현 순서, 화면 구조, 정책 결정, API 우선순위를 정리한 기준 문서다.  
설계 문서보다 더 실행 중심으로 적고, 진행 현황 문서보다 더 계획 중심으로 적는다.

즉 이 문서에서는 아래를 관리한다.

- 어떤 순서로 구현할지
- 각 기능에서 어떤 정책을 따를지
- 프론트/백엔드가 어떤 구조로 연결될지
- 더미 데이터와 테스트를 어떻게 진행할지

## 2. 전체 구현 방향

현재 프로젝트는 아래 흐름으로 진행한다.

1. 마이페이지 핵심 기능 구현
2. 대시보드 요약 및 분석 기능 구현
3. 리뷰 / 찜 / 회원정보 / 배송지 보강
4. 이후 관리자/차트/추가 기능 확장

핵심 기준:

- 먼저 “보이는 흐름”을 만든다.
- 그다음 더미가 아닌 실제 API로 바꾼다.
- 마지막에 세부 기능과 정책을 보강한다.

## 3. 화면 구조 계획

### 3.1 마이페이지

마이페이지는 관리형 화면으로 정의했다.

구성:

- 상단 프로필 요약 카드
- 하단 탭 영역
  - 주문내역
  - 찜한상품
  - 리뷰관리

세부 기준:

- 주문내역은 카드형 목록 + 상세 보기 구조
- 찜한상품은 카드 그리드형
- 리뷰관리는 작성 가능한 리뷰 / 내가 작성한 리뷰 2영역 구조
- 회원정보 수정은 모달 또는 별도 관리 패널
- 배송지 관리는 모달로 처리하되, 목록과 입력 모드는 분리

### 3.2 대시보드

대시보드는 분석형 화면으로 정의했다.

구성:

- 상단 KPI 카드 4개
- 중단 차트 2개
  - 월별 절약 금액
  - 품목별 절약 분석
- 하단 패턴 영역
  - 평균 구매 단가
  - 절약률
  - 최다 구매 품목
  - 최근 구매 상품

### 3.3 메뉴 구조

- 메인
- 시세분석
- 상품
- 레시피
- 대시보드
- 마이페이지

기준:

- 마이페이지와 대시보드는 별도 메뉴로 분리
- 한 화면에서 탭처럼 섞지 않음

## 4. 백엔드 구현 순서 계획

### 4.1 1순위

- 주문 목록 조회
- 주문 상세 조회

이유:

- 마이페이지 중심 기능
- 리뷰관리와 대시보드의 기반 데이터
- 더미 데이터로 바로 검증 가능

### 4.2 2순위

- 대시보드 요약 API

이유:

- 주문 기반 집계로 바로 연결 가능
- 사용자 체감 가치가 큼

### 4.3 3순위

- 회원정보 조회 / 수정
- 배송지 목록 / 추가 / 기본 배송지 변경

이유:

- 주문/리뷰보다 독립적
- 마이페이지 사용성을 올리는 핵심 기능

### 4.4 4순위

- 리뷰관리 API
  - 작성 가능한 리뷰
  - 내가 작성한 리뷰
  - 작성/수정/삭제

### 4.5 5순위

- 찜한상품 API

### 4.6 6순위

- 대시보드 차트 / 패턴 API

## 6. 정책 결정 사항

### 6.1 주문 / 절약 정책

- 주문 시점 절약률은 `OFT_ORDER_ITEM.SAVING_RATE` 컬럼으로 저장
- 주문 상세와 대시보드는 주문 시점 저장값을 기준으로 표시
- 조회 시 실시간 재계산은 하지 않음

### 6.2 찜한상품 정책

- 찜 목록은 상품 현재 상태 기준 표시
- 혜택 문구는 실시간 표시용 값으로 처리
- `savingRate >= 10` 이면 혜택 문구 노출

### 6.3 리뷰 정책

- 작성 가능 조건:
  - 배송완료
  - 해당 주문상품 리뷰 없음
- 리뷰 삭제 후 재작성 가능
- 수정/삭제는 본인 리뷰만 가능

### 6.4 배송지 정책

- 기본 배송지는 1개만 허용
- 기본 배송지 삭제 전에 다른 배송지를 먼저 기본 배송지로 바꿔야 함
- 자동 대체 지정은 하지 않음
- 배송지 추가 UI는 목록과 분리된 단일 입력 모드 사용
- 배송지 삭제 기능은 제공하되, 기본 배송지 삭제 제한 정책을 우선 적용

### 6.5 사용자 식별 정책

- 로그인 미구현 단계에서는 `X-USER-NO` 헤더 사용
- 현재 테스트 기준 사용자:
  - `USER_NO = 1`
  - `USER_ID = mypage01`

## 7. 더미 데이터 계획

### 7.1 최소 주문 데이터

- 사용자 1명
- 주문 2건 이상
- 주문상품 3건 이상
- 배송완료 / 배송중 상태 혼합
- 리뷰 있음 / 없음 혼합

목적:

- 주문 목록
- 주문 상세
- 리뷰 작성 가능 여부

### 7.2 대시보드 강화 데이터

- 주문월을 3개월 이상으로 분산
- 최다 구매 품목이 드러나도록 특정 상품 재구매 추가

목적:

- 월별 차트 검증
- 최다 구매 품목 검증

## 8. 테스트 계획

### 주문

- 목록 정상 조회
- 상세 정상 조회
- 같은 사용자 기준 상세 접근
- 배송 상태 / 리뷰 상태 반영 확인

### 회원정보

- 조회
- 수정
- 저장 후 즉시 반영

### 배송지

- 목록 조회
- 배송지 추가
- 첫 주소 기본 배송지 처리
- 기본 배송지 변경
- 배송지 삭제
- 기본 배송지 삭제 제한 정책 확인

### 대시보드

- 요약 카드 값 검증
- 더미 데이터 기준 기대값 비교

## 9. 현재 기준 남은 구현 우선순위

1. 리뷰관리 API 및 화면 연동
2. 찜한상품 API 및 화면 연동
3. 회원정보 중복 체크 / 비밀번호 변경
4. 배송지 수정
5. 대시보드 차트 / 패턴 API 연동

## 10. 문서 운영 규칙

- 실제 진행 상태는 `chl/progress.md`에 기록
- 구현 순서/정책 변경은 이 문서에 기록
- 설계 원칙 변경은 `docs` 문서에 기록
