# 주문/배송 분리 UI 와이어프레임 초안

## 1. 목적
- 고객용 `내 주문`, 운영자용 `주문 관리`, 배송사용 `배송 관리`를 실제 화면 단위로 분리 설계한다.
- 본 문서는 디자인 시안이 아니라 구현 전 레이아웃, 정보 위계, 액션 배치 기준을 정하는 와이어프레임 초안이다.

## 2. 공통 UI 원칙
- 상태는 `주문 상태`, `취소 상태`, `배송 상태`를 분리해 보여준다.
- 목록 화면에서는 `빠른 판단`, 상세 화면에서는 `처리와 이력 확인`에 집중한다.
- 버튼은 현재 상태에서 가능한 액션만 보인다.
- 고객/운영자/배송사 화면의 버튼 명칭과 상태 문구는 서로 다르게 과장하지 않고 일관되게 유지한다.

### 3.1 목록 화면 구조

- 기간 필터

  - 취소 상태
  - 배송 상태
- 검색창
  - 주문번호 검색

중단 목록 카드/행
- 주문일시
- 주문번호
- 상품 대표 이미지 1~3장
- 상품 요약
- 총 결제 금액
- 주문 상태
- 취소 상태
- 배송 상태
- 배송 조회 버튼
- 주문 상세 버튼

하단
- 페이지네이션 또는 더보기

### 3.2 상세 화면 구조
좌측 또는 상단 주요 정보 카드
- 주문번호
- 주문일시

- 취소 상태
- 배송 상태

배송 정보 카드
- 배송사
- 송장번호
- 수취인
- 연락처
- 주소
- 배송 메시지

상품 목록 카드
- 상품 이미지
- 상품명
- 수량
- 상품 금액
- 리뷰 작성 가능 여부

배송 추적 타임라인
- 송장 등록
- 제품 접수
- 배송중
- 배송완료

하단 액션 영역
- 취소 요청
- 배송 조회
- 리뷰 작성
- 구매확정

### 3.3 고객 화면 노출 규칙
- `취소 요청`은 `NOT_STARTED`일 때만 노출
- `리뷰 작성`은 `DELIVERED` + 미작성일 때만 노출
- `구매확정`은 `DELIVERED` + 미확정일 때만 노출

- `배송완료`는 `IN_TRANSIT`일 때만 노출

## 6. 모바일 대응 방향
- 고객용 `내 주문`은 카드형 유지
- 운영자/배송사 화면은 모바일에서
  - 목록을 카드형으로 축소
  - 상세는 섹션 아코디언 구조 사용
- 처리 버튼은 모바일에서 하단 고정 액션 바 고려

## 7. 상태 라벨/배지 기준

### 7.1 주문 상태
- `PAYMENT_COMPLETED` → `결제완료`
- `ORDER_ACCEPTED` → `주문 수락`
- `ORDER_REJECTED` → `주문 거절`

### 7.2 취소 상태
- `NONE` → 표시 생략 또는 `정상`
- `CANCEL_REQUESTED` → `취소 요청`
- `CANCEL_ACCEPTED` → `취소 수락`
- `CANCEL_REJECTED` → `취소 거절`

### 7.3 배송 상태
- `NOT_STARTED` → `배송 준비`
- `WAYBILL_ASSIGNED` → `송장 등록`
- `PICKED_UP` → `제품 접수`
- `IN_TRANSIT` → `배송 중`
- `DELIVERED` → `배송 완료`

  - `취소 수락`
  - `취소 거절`
- 배송사
  - `송장 등록`
  - `제품 접수`
  - `배송중`
  - `배송완료`

## 9. 구현 우선순위 제안
1. 운영자용 `주문 관리`
2. 배송사용 `배송 관리`
3. 고객용 `내 주문`

이유:
- 고객 화면은 운영자/배송사 상태가 먼저 정리되어야 자연스럽다.
- 실제 상태 변경의 시작점은 운영자와 배송사 화면이다.
