# 2. 프로젝트 개요

## 2.1 문제 정의

국내 농산물 유통은 중간 단계가 많아 가격 정보가 소비자에게 직관적으로 전달되지 않는 경우가 많다. 반면 공공기관은 도·소매 가격, 경매 정보, 가격 추세 등 유용한 데이터를 공개하고 있다. 문제는 이 데이터를 일반 사용자가 이해하기 쉬운 구매 경험으로 전환한 서비스가 많지 않다는 점이다.

본 프로젝트는 이 간극을 줄이는 데 목적이 있다. 사용자는 복잡한 시세 데이터를 직접 해석하지 않아도, 상품 상세 화면과 대시보드에서 **현재 판매가가 평균 시세 대비 얼마나 유리한지**를 직관적으로 확인할 수 있다.

## 2.2 서비스 한 줄 정의

> 공공 농산물 시세 데이터를 기반으로, 플랫폼이 직접 매입·소분한 상품을 합리적인 가격에 판매하고, 사용자에게 구매 절약 효과를 데이터로 보여주는 농산물 커머스 서비스

## 2.3 서비스 핵심 가치

| 구분 | 설명 |
|---|---|
| 가격 투명성 | 공공 시세를 기준으로 상품 가격을 비교해 사용자가 가격 판단을 쉽게 할 수 있게 함 |
| 구매 설득력 | “평균가 이하” 뱃지, 절약 금액, 추세 그래프를 통해 구매 이유를 명확하게 제공 |
| 운영 현실성 | 생산자와 직접 채팅/협상하는 구조가 아니라 플랫폼이 직접 매입·소분하는 구조라 MVP 구현과 운영이 현실적 |
| 재구매 유도 | 개인 대시보드에서 누적 절약 금액, 월별 절약 금액, 자주 사는 품목을 제공해 반복 구매 동기 부여 |
| 콘텐츠 확장성 | 구매 상품과 연결된 레시피/영양정보를 제공해 체류 시간과 만족도를 높임 |

## 2.4 서비스 대상 사용자

| 사용자 유형 | 주요 니즈 | 기대 효과 |
|---|---|---|
| 1인 가구 / 자취생 | 적은 단위, 합리적인 가격, 쉬운 조리 연결 | 소분 상품 구매 + 레시피 추천 |
| 가성비 중심 사용자 | 평균가 대비 얼마나 저렴한지 확인 | 시세 비교와 절약 데이터 제공 |
| 반복 구매 사용자 | 자주 사는 품목 정리, 월별 소비 파악 | 개인 대시보드 |
| 관리자 | 매입, 소분, 재고, 주문, 배송 상태를 한 흐름으로 관리 | 운영 효율 향상 |

# 3. 서비스 범위와 운영 원칙

## 3.1 확정 운영 정책

<div class="decision">
<strong>핵심 정책 1 — 거래 구조</strong><br>
본 서비스는 사용자 간 게시판형 직거래가 아니라, <strong>플랫폼이 농산물을 직접 매입</strong>한 뒤 상품 단위로 <strong>소분하여 판매</strong>하는 구조를 기본으로 한다.
</div>

<div class="decision">
<strong>핵심 정책 2 — 가격 비교 기준</strong><br>
상품의 판매가는 공공 시세 데이터(예: KAMIS 등)와 비교되어 평균가 대비 차액, 절약률, 평균가 이하 여부를 계산한다.
</div>

<div class="decision">
<strong>핵심 정책 3 — 사용자 가치 제안</strong><br>
단순히 “싸게 판다”가 아니라, 사용자가 실제 구매 이후 <strong>누적 절약 금액</strong>과 <strong>월별 절약 흐름</strong>을 확인할 수 있어야 한다.
</div>

| 구분 | 포함 범위(In Scope) | 제외/후순위(Out of Scope) |

## 4.2 핵심 사용자 여정

### 시나리오 A — 첫 방문 사용자
1. 메인 배너에서 제철 상품/절약 혜택 확인
2. 상품 상세에서 평균가 대비 절약 정보를 확인
3. 회원가입 후 장바구니에 추가
4. 주문 완료 후 마이페이지에서 첫 절약 금액 확인

### 시나리오 B — 반복 구매 사용자
1. 로그인 후 대시보드에서 최근 구매와 월별 절약 금액 확인
2. 자주 구매한 품목을 중심으로 추천 상품 탐색
3. 필요한 경우 관련 레시피를 확인 후 재구매 진행

### 시나리오 C — 관리자 운영
1. 매입 배치 등록
2. 소분 이력 기록 및 재고 생성
3. 상품 등록 후 이미지 업로드
4. 주문 확인 및 배송 상태 변경
5. 통계 집계 결과 확인

# 6. 대시보드 지표 정의

## 6.1 핵심 계산식

<div class="box">
<strong>절약 금액</strong> = (주문 시점 평균 시세 − 실제 구매 단가) × 구매 수량
</div>

단, 운영 정책에 따라 평균가보다 비싸게 판매된 경우는 아래 두 방식 중 하나를 선택할 수 있다.

1. 음수 절약 금액을 허용하지 않고 0으로 처리  
2. 실제 차액을 저장하여 “평균가 대비 불리한 구매”도 표시

현재 기준안은 **사용자 경험 단순화**를 위해 **0 미만은 0 처리**를 우선안으로 둔다.

# 12. 결론

이 프로젝트의 강점은 **데이터 분석 기능이 실사용 구매 경험과 직접 연결되어 있다는 점**이다.  
단순 쇼핑몰이 아니라, 공공 데이터를 활용하여 가격의 설득력을 만들고, 구매 이후에는 절약 효과를 가시화한다는 점에서 포트폴리오 차별성이 크다.

또한 플랫폼 직접 매입·소분 구조를 채택함으로써 MVP 운영 모델이 현실적이며, Oracle 기반 데이터 설계와 개인 대시보드 기능까지 포함하여 **커머스 + 데이터 제품**의 특성을 함께 보여줄 수 있다.



# 추천 시스템 전략 (추가)

본 서비스는 시세 데이터와 콘텐츠 데이터를 결합하여 **추천 기반 장보기 경험**을 제공한다.

추천 데이터는 아래 요소를 기반으로 생성된다.

- 시세 분석 데이터
- 사용자 구매 데이터
- 인기 농산물 트렌드 (네이버 데이터랩)
- 레시피 데이터

## 추천 데이터 흐름

시세 데이터 분석
↓
평균가 이하 상품 추천
↓
구매 타이밍 추천
↓
인기 농산물 분석
↓
레시피 매칭
↓
밀키트 추천
↓
추천 페이지 노출

## 추천 페이지 구성

추천 페이지에서는 다음 데이터를 통합적으로 제공한다.

- 구매 타이밍 추천 상품
- 평균가 이하 상품
- 인기 농산물
- 추천 레시피
- 밀키트 추천

## 인기 농산물 데이터

인기 농산물 데이터는 **네이버 데이터랩 검색 트렌드 API**를 활용한다.

활용 방식
- 농산물 키워드 검색 관심도 분석
- 관심도 상승 농산물 추천
- 해당 농산물 기반 레시피 추천
