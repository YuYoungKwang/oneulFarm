# oneulFarm 최종발표 시연 대본

## 1. 시연 방향

- 이번 시연은 `구매 시나리오`, `관리자 매입/소분 시나리오`, `맞춤식단/AI 챗봇 시나리오` 세 가지로 진행한다.
- 단순 기능 나열보다 `왜 이렇게 설계했는지`를 함께 설명하는 방식으로 진행한다.
- 핵심 메시지는 `oneulFarm은 레시피와 식단 맥락 안에서 재료 구매까지 이어지게 만든 농산물 커머스`라는 점이다.

## 2. 시연 오프닝

- 시작 멘트
  - "이제부터는 실제 화면을 통해 oneulFarm의 핵심 흐름을 시연으로 보여드리겠습니다."
  - "시연은 구매 사용자 흐름, 관리자 운영 흐름, 그리고 맞춤식단 AI 흐름 순서로 진행하겠습니다."
  - "보시면서 봐주시면 좋은 포인트는, 저희가 기능 하나하나를 따로 만든 것이 아니라 구매까지 이어지는 흐름으로 연결했다는 점입니다."

## 3. 시나리오 1. 구매 시나리오

### 3.1 시나리오 목표

- 핵심 메시지
  - "첫 번째는 실제 구매 시나리오입니다."
  - "이 시나리오에서는 사용자가 메인에서 출발해서 레시피를 보고, 두 개 이상의 레시피 재료를 장바구니에 담고, 구매와 주문 관리, 리뷰까지 이어지는 흐름을 보여드리겠습니다."
  - "이렇게 구성한 이유는 oneulFarm이 단순 상품 쇼핑몰이 아니라, 레시피를 중심으로 장보기가 이어지는 구조라는 점을 보여주기 위해서입니다."

### 3.2 메인 -> 레시피 선택

- 이동 화면
  - `#/`
  - `#/recipes`
  - `#/recipes/{recipeNo}`
- 설명 멘트
  - "먼저 메인페이지입니다. 현재 메인은 히어로 슬라이드, 지금 뜨는 상품으로 만드는 레시피, 그리고 지금 담기 좋은 제철 재료 중심으로 구성되어 있습니다."
  - "특히 메인에서 바로 레시피, 제철 상품, AI 맞춤식단으로 진입할 수 있게 만든 점이 핵심입니다."
  - "저희가 이렇게 만든 이유는 사용자가 상품만 보는 것이 아니라, 무엇을 만들지와 어떤 재료를 살지를 메인 첫 화면에서 바로 연결해 보기 위해서입니다."
  - "이제 레시피 목록으로 이동해서 첫 번째 레시피를 선택해보겠습니다."

### 3.3 레시피 상세 -> 장바구니 담기

- 보여줄 포인트
  - 레시피 상세
  - 재료 목록
  - 구매 가능한 재료
  - 장바구니 담기
- 설명 멘트
  - "레시피 상세에서는 재료 정리, 분량 조절, 리뷰와 함께 장바구니에 담을 품목을 따로 확인할 수 있습니다."
  - "즉 레시피를 보는 화면 안에서 어떤 재료를 실제로 살 수 있는지까지 바로 이어집니다."
  - "이 부분이 중요한 이유는 레시피가 콘텐츠로 끝나는 것이 아니라 실제 구매 전환의 출발점이 되도록 설계했기 때문입니다."
  - "여기서 첫 번째 레시피 재료를 장바구니에 담아보겠습니다."

### 3.4 다시 레시피 선택 -> 두 번째 레시피 추가

- 이동 흐름
  - 장바구니 확인
  - 다시 레시피 목록 또는 상세로 이동
  - 두 번째 레시피 선택
  - 재료 추가
- 설명 멘트
  - "이번에는 장바구니에 담긴 구성을 먼저 확인한 뒤, 다시 레시피로 돌아가서 두 번째 레시피를 추가해보겠습니다."
  - "최소 두 개의 레시피를 담아보는 이유는, 실제 사용자가 한 끼만 장보는 것이 아니라 여러 식사 계획을 함께 고려할 수 있다는 점을 보여주기 위해서입니다."
  - "즉 장바구니가 단순 상품 목록이 아니라, 레시피 단위 구매 흐름을 담는 구조라는 점을 확인하실 수 있습니다."

### 3.5 장바구니 -> 구매 -> 결제

- 이동 화면
  - `#/cart`
  - `#/checkout`
- 설명 멘트
  - "이제 장바구니에서 두 레시피 재료가 어떻게 묶여 담겼는지 확인하고 구매로 넘어가겠습니다."
  - "현재 장바구니는 레시피 담기와 일반 담기를 구분해서 보여주고, 수량과 예상 절약 금액까지 한 번에 확인할 수 있게 되어 있습니다."
  - "저희가 장바구니와 결제 흐름을 이렇게 만든 이유는 레시피에서 유입된 사용자가 맥락이 끊기지 않은 상태로 주문까지 이어지게 하기 위해서입니다."
  - "즉 사용자는 단순히 상품을 고르는 것이 아니라, 식사 계획 안에서 필요한 재료를 정리하고 구매하게 됩니다."
  - "체크아웃에서는 기본 배송지와 결제 수단을 확인하고 주문을 마무리할 수 있습니다."
  - "결제까지 진행하면 주문이 생성되고, 이후에는 마이페이지와 주문관리에서 상태를 확인할 수 있습니다."
  - "또 이 단계에서 주문 취소가 가능하다는 점도 함께 설명드리겠습니다."

### 3.6 마이페이지 / 주문관리 -> 취소 가능 설명

- 이동 화면
  - `#/mypage/orders`
  - 필요 시 `#/dashboard`
- 설명 멘트
  - "주문이 완료된 뒤에는 마이페이지의 주문관리 화면에서 주문 내역과 배송 현황을 함께 확인할 수 있습니다."
  - "현재 화면에서는 주문 목록과 선택한 주문의 상세 정보가 같이 보이기 때문에, 사용자가 상태를 한눈에 확인하기 좋습니다."
  - "또 조건에 따라 취소 요청도 가능하도록 구성했습니다."
  - "이 기능을 넣은 이유는 구매 이후 단계까지 하나의 사용자 흐름으로 완성해야 실제 커머스 서비스처럼 보이기 때문입니다."

### 3.7 관리자 주문 관리 -> 취소 수락 가능 설명 -> 주문 접수

- 이동 화면
  - `#/admin/orders`
- 설명 멘트
  - "이제 관리자 주문 관리 화면으로 이동해보겠습니다."
  - "관리자 화면에서는 들어온 주문을 확인하고 상태를 변경할 수 있습니다."
  - "먼저 취소 요청이 들어온 주문은 관리자가 취소 수락 처리를 할 수 있다는 점만 설명하고 넘어가겠습니다."
  - "이후 정상 주문에 대해서는 주문 접수 처리를 진행하겠습니다."
  - "이렇게 만든 이유는 사용자 주문 흐름과 관리자 운영 흐름이 실제로 연결되어야 서비스 전체 구조가 완성되기 때문입니다."

### 3.8 다시 사용자 -> 배송 확인 -> 리뷰 작성 / 수정 / 삭제

- 이동 화면
  - `#/mypage/orders`
  - `#/mypage/activity`
- 설명 멘트
  - "관리자에서 주문이 접수된 뒤에는, 사용자는 다시 마이페이지 주문관리에서 배송 상태를 확인할 수 있습니다."
  - "그리고 배송 완료 이후에는 내 활동 화면으로 이동해서 리뷰를 관리할 수 있습니다."
  - "현재 내 활동은 찜한 상품과 리뷰 관리로 나뉘어 있고, 작성 가능한 리뷰와 내가 작성한 리뷰를 구분해서 볼 수 있습니다."
  - "리뷰는 작성뿐 아니라 수정과 삭제까지 가능하도록 구성했습니다."
  - "이 부분을 넣은 이유는 구매 이후의 사용자 경험까지 닫혀 있어야, 단순 구매 데모가 아니라 실제 서비스 흐름으로 보일 수 있기 때문입니다."

### 3.9 시나리오 1 마무리 멘트

- 정리 멘트
  - "정리하면 첫 번째 시나리오는 메인에서 시작해 레시피를 보고, 여러 레시피 재료를 장바구니에 담고, 구매와 주문관리, 리뷰까지 이어지는 전체 구매 흐름을 보여주는 시나리오입니다."

## 5. 시나리오 3. 맞춤식단 / AI 챗봇 시나리오

### 5.1 시나리오 목표

- 핵심 메시지
  - "세 번째는 맞춤식단과 AI 챗봇 시나리오입니다."
  - "이 시나리오에서는 AI가 식단을 제안하고, 필요한 재료를 장바구니와 구매 흐름으로 연결한 뒤, 구매 후에는 내 식단 관리에서 다시 확인할 수 있는 흐름을 보여드리겠습니다."
  - "이렇게 구성한 이유는 oneulFarm의 AI 기능이 단순 추천으로 끝나는 것이 아니라, 실제 장보기와 식단 관리로 이어지는 점을 보여주기 위해서입니다."

### 5.2 AI 챗봇 -> 맞춤식단 생성

- 이동 화면
  - `#/meal-plan`
- 설명 멘트
  - "먼저 맞춤식단 AI 화면입니다."
  - "현재 화면은 채팅 목록과 대화 영역으로 구성되어 있어서, 이전 식단 대화도 이어서 관리할 수 있습니다."
  - "사용자가 건강 상태나 식단 조건을 입력하면, AI가 식단 요약과 날짜별 식단, 그리고 필요한 재료 목록을 함께 생성합니다."
  - "저희가 이렇게 만든 이유는 사용자가 단순히 상품을 찾는 것이 아니라, 자신의 식사 계획을 먼저 세우고 그에 맞춰 장보기를 하게 만들기 위해서입니다."

### 5.3 맞춤식단 -> 장바구니

  - 장바구니 후보
  - 예상 금액

  - "판매 중인 재료는 장바구니 확인 영역에서 바로 담을 수 있게 연결되어 있습니다."
  - "즉 AI 결과가 정보 제공에서 끝나는 것이 아니라, 실제 구매 가능한 형태로 이어지도록 설계했습니다."
  - "여기서 필요한 재료를 장바구니에 담아보겠습니다."

### 5.4 장바구니 -> 구매 후 -> 내 식단 관리 확인

## 8. 시연 운영 메모

- 구매 시나리오에서는 `취소 가능`, `관리자 취소 수락 가능`까지만 설명하고 오래 머물지 않는다.
- 구매 시나리오에서는 최소 두 개의 레시피를 담아 `레시피 기반 장보기`라는 점을 강조한다.
- 메인 설명은 `히어로 슬라이드`, `지금 뜨는 상품으로 만드는 레시피`, `지금 담기 좋은 제철 재료`, `AI 맞춤식단 진입` 중심으로 짧게 정리한다.
- 관리자 시나리오는 `운영 가능성`을 보여주는 목적이므로 상세 입력보다 흐름 설명에 집중한다.
- 맞춤식단 시나리오는 `AI 생성 -> 장바구니 -> 구매 후 내 식단 관리 확인` 순서를 꼭 유지한다.
- AI 식단 설명에서는 `채팅 목록`, `식단 요약`, `날짜별 식단`, `합산 재료`, `판매중인 재료`, `내 식단 관리 연결`까지가 현재 구현 범위라는 점을 기준으로 말한다.
- 시연 중 기능 하나를 보여줄 때마다 `왜 이 기능이 필요한지`를 한 문장씩 붙여 설명한다.
