# oneulFarm 시연 런북

## 1. 시연 원칙
- 시연은 `사용자 가치 -> 운영 가치 -> 기술 구조` 순서로 간다.
- 한 화면에서 오래 머물지 않는다.
- 모든 화면 설명에는 `이 화면이 왜 필요한지` 한 문장을 포함한다.
- 외부 상태에 영향을 받을 수 있는 구간은 짧게 확인하고 넘어간다.

## 2. 고정 시연 순서

| 1 | `#/` | 메인 배너, 추천 상품, 시세 기반 서비스 소개 | "메인은 상품 나열이 아니라 서비스 방향을 처음 설명하는 허브입니다." | 메인 캡처 이미지 |

| 3 | `#/recipes` | 재료 키워드 검색, 정렬, 레시피 목록 | "레시피는 구매 후 활용을 돕는 동시에 다시 상품 탐색으로 이어지는 콘텐츠입니다." | 레시피 목록 캡처 이미지 |

| 7 | `#/cart` | 장바구니 구성 확인 | "탐색에서 구매로 자연스럽게 이어지는 흐름입니다." | 장바구니 캡처 이미지 |
| 8 | `#/checkout` | 배송지, 주문 정보, 결제 진입 구조 | "실제 주문 직전까지 필요한 정보가 연결되어 있습니다." | 체크아웃 캡처 이미지 |
| 9 | `#/mypage` | 계정 허브, 프로필 요약 | "구매 이후 활동도 서비스 경험의 일부로 설계했습니다." | 마이페이지 캡처 이미지 |
| 10 | `#/mypage/activity` | 찜한 상품, 리뷰 관리 | "찜과 리뷰가 실제 상품 데이터와 연결됩니다." | 활동 화면 캡처 이미지 |
| 11 | `#/mypage/orders` | 주문 목록, 상세, 필터 | "구매 이후 이력을 단순 목록이 아니라 관리 가능한 화면으로 분리했습니다." | 주문관리 캡처 이미지 |
| 12 | `#/dashboard` | 누적 절약, 월별 흐름, 품목별 절약 | "절약을 체감하게 만드는 화면이 대시보드입니다." | 대시보드 캡처 이미지 |
| 13 | `#/admin` | 관리자 허브 | "사용자 화면만이 아니라 실제 운영 구조도 구현했습니다." | 관리자 메인 캡처 이미지 |
| 14 | `#/admin/purchase` | 매입, 견적, 소분 흐름 | "매입과 소분이 사용자 화면의 가격 정보와 연결됩니다." | 매입/소분 캡처 이미지 |
| 15 | `#/admin/products` | 상품 수정, 이미지, 판매 상태 | "운영 데이터가 바로 판매 화면 품질로 이어집니다." | 상품관리 캡처 이미지 |
| 16 | `#/admin/content` | 배너, 레시피 매핑 등 콘텐츠 운영 | "레시피와 배너까지 운영 화면에서 관리해 사용자 경험을 지속적으로 보완할 수 있습니다." | 콘텐츠 관리 캡처 이미지 |
| 17 | `#/admin/orders` | 주문 상태 관리 | "주문 이후 처리까지 관리자 화면에서 이어집니다." | 주문관리 캡처 이미지 |

## 3. 시간 배분

| 구간 | 권장 시간 |
|---|---|
| 오프닝 + 문제 정의 | 1분 30초 |
| 서비스 소개 | 40초 |
| 사용자 시연 | 4분 30초 |
| 관리자 시연 | 2분 30초 |
| 기술 구조 | 2분 30초 |
| 차별점 + 마무리 | 1분 |

## 4. 리허설 전 체크리스트
- 로그인 계정 1개를 미리 로그인해 둔다.
- 배송지 기본값이 있는지 확인한다.
- 주문 이력이 최소 1건 이상 있는지 확인한다.
- 대시보드 데이터가 비어 있지 않은지 확인한다.
- 활동 화면에서 찜 상품과 리뷰 데이터가 보이는지 확인한다.
- 레시피 목록과 레시피 상세가 정상 조회되는지 확인한다.
- 레시피 상세에서 구매 가능한 재료 hover 카드가 보이는지 확인한다.
- 관리자 화면 진입 상태를 미리 맞춘다.
- 시세분석에서 검색할 품목 1개를 고정한다.
- 레시피 시연에 사용할 재료 키워드 1개와 레시피 1개를 고정한다.
- 상품 상세에 사용할 대표 상품 1개를 고정한다.
- 외부 결제나 외부 API 실패 시 대체할 캡처 이미지를 준비한다.

## 6. 실제 라우트 메모
- 메인: `#/`, `#/main`
- 시세분석: `#/price-analysis`
- 레시피 목록: `#/recipes`
- 레시피 상세: `#/recipes/:recipeNo`
- 상품 목록: `#/products`
- 상품 상세: `#/products/:productNo`
- 장바구니: `#/cart`
- 체크아웃: `#/checkout`
- 마이페이지: `#/mypage`
- 활동: `#/mypage/activity`
- 주문관리: `#/mypage/orders`
- 대시보드: `#/dashboard`
- 관리자: `#/admin`
- 관리자 상품: `#/admin/products`
- 관리자 매입/소분: `#/admin/purchase`
- 관리자 주문: `#/admin/orders`
- 관리자 회원: `#/admin/users`
- 관리자 콘텐츠: `#/admin/content`

## 7. 관리자 진입 메모
- 현재 프론트 기준 관리자 진입은 `oneulFarmAdminMode` 상태가 켜져 있어야 한다.
- 발표 전 브라우저 콘솔에서 아래 한 줄로 상태를 맞출 수 있다.

```js
localStorage.setItem('oneulFarmAdminMode', 'true');
```

- 발표 종료 후 일반 사용자 화면으로 돌아갈 때는 아래 한 줄을 사용한다.

```js
localStorage.removeItem('oneulFarmAdminMode');
```

## 8. 데모 범위와 설명 범위 구분

| 항목 | 권장 방식 | 설명 |
|---|---|---|
| 메인, 상품, 마이페이지, 주문관리, 대시보드 | 실제 시연 중심 | 현재 구현과 연결성이 높아 발표 핵심으로 사용하기 좋다. |
| 시세분석 | 실제 시연 중심 | oneulFarm의 핵심 차별점이므로 반드시 직접 보여준다. |
| 레시피 | 실제 시연 중심 | 재료 hover 시세 요약, 연관 상품, 한번에 담기를 통해 추가 구매 유도를 설명할 수 있다. |
| 관리자 매입/소분 | 실제 시연 중심 | 운영 구조까지 구현했다는 점을 증명하는 구간이다. |
| 결제 | 짧은 시연 + 설명 병행 | 환경에 따라 흔들릴 수 있으므로 체크아웃 구조 위주로 보여주고 승인 흐름은 보조 설명으로 정리한다. |
| 외부 API 실패 가능 구간 | 설명 중심 전환 가능 | 차트나 캡처 화면으로 즉시 전환한다. |

## 9. 실패 대응 멘트
- 시세 응답이 늦을 때:
  - "시세 데이터는 외부 소스와 연결되기 때문에 응답 편차가 있을 수 있습니다. 핵심은 이 데이터를 상품 비교와 대시보드까지 연결했다는 점입니다."
- 체크아웃 상태가 흔들릴 때:
  - "주문 직전까지의 흐름은 이 화면처럼 연결되어 있고, 발표에서는 핵심 가치인 시세 비교와 절약 체감에 집중하겠습니다."
- 관리자 데이터가 예상과 다를 때:
  - "관리자 화면은 매입과 소분, 상품 관리, 주문 관리가 한 흐름으로 이어진다는 점을 중심으로 봐주시면 됩니다."

## 10. 최종 검증 기준
- 발표 순서가 실제 사이트 동선과 일치한다.
- 각 화면마다 `왜 필요한지`와 `무엇이 차별점인지`를 한 문장씩 말한다.
- 대시보드 설명에서 반드시 `절약 체감`을 언급한다.
- 관리자 설명에서 반드시 `매입 -> 소분 -> 상품화 -> 주문` 연결 구조를 언급한다.
- 레시피 설명에서 반드시 `재료 탐색 -> hover 시세 확인 -> 연관 상품/한번에 담기 -> 추가 구매` 구조를 언급한다.
- 기술 설명 전에 이미 사용자 가치가 충분히 전달되어 있어야 한다.
